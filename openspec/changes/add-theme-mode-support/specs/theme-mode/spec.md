## ADDED Requirements

### Requirement: 应用提供可持久化的三态主题模式
系统 SHALL 提供“跟随系统”“日间模式（LIGHT）”“夜间模式（DARK）”三种主题模式，并将用户选择持久化为稳定值；首次使用、旧版本升级后没有主题偏好、或持久化值无法识别时，系统 SHALL 使用“跟随系统”。

#### Scenario: 没有已保存选择时默认跟随系统
- **WHEN** 用户首次打开应用或升级后尚未保存主题模式
- **THEN** 系统将当前主题模式视为“跟随系统”
- **AND** 不要求用户先进入设置页完成初始化

#### Scenario: 用户保存显式主题模式
- **WHEN** 用户选择“日间模式（LIGHT）”或“夜间模式（DARK）”
- **THEN** 系统持久化该模式的稳定标识
- **AND** Activity 重建或应用进程重启后继续恢复相同选择

#### Scenario: 已保存值无效时安全回退
- **WHEN** 系统读取到空值、未知值或无法识别的主题模式标识
- **THEN** 系统回退到“跟随系统”
- **AND** 应用继续正常渲染而不因偏好损坏退出

### Requirement: 主题模式以单一规则解析最终明暗状态
系统 SHALL 仅在共享主题解析边界读取系统明暗状态，并根据主题模式生成唯一的最终明暗结果；普通页面和 feature 不得再次使用系统状态覆盖该结果。

#### Scenario: 跟随系统模式响应系统变化
- **WHEN** 当前模式为“跟随系统”且系统在浅色与深色之间变化
- **THEN** 应用使用新的系统明暗状态重新解析主题
- **AND** 所有普通页面使用更新后的结果

#### Scenario: 显式浅色覆盖系统深色
- **WHEN** 当前模式为“浅色”且系统处于深色
- **THEN** 应用仍以浅色主题渲染普通页面和通用组件

#### Scenario: 显式深色覆盖系统浅色
- **WHEN** 当前模式为“深色”且系统处于浅色
- **THEN** 应用仍以深色主题渲染普通页面和通用组件

### Requirement: 所有 UI 入口共享同一主题选择
系统 SHALL 通过 app UI 进程内的单一主题状态源，将同一个主题选择传播到主壳层、设置页、播放器宿主、详情页、其他独立 Activity 和 `feature-discovery` 搜索页；主题状态不得进入独立播放进程或播放契约。

#### Scenario: 设置页切换后活跃页面即时生效
- **WHEN** 用户在设置页选择不同主题模式
- **THEN** 当前设置页立即使用新主题重新渲染
- **AND** 已打开且仍活跃的其他 Compose 根从同一状态源获得新选择
- **AND** 系统不要求手动重建 Activity 才能生效

#### Scenario: 新打开页面继承当前选择
- **WHEN** 用户保存主题模式后打开搜索页、播放器页、详情页或其他独立 Activity
- **THEN** 新页面使用与主壳层相同的主题选择和解析结果
- **AND** feature 不自行读取另一份主题偏好

#### Scenario: 主题状态不影响后台播放
- **WHEN** 用户切换主题模式或应用恢复已保存主题
- **THEN** 播放服务的队列、播放状态和跨进程契约保持不变

### Requirement: 系统栏恢复使用已解析主题并保留内容覆盖
系统 SHALL 让普通页面的状态栏和导航栏图标明暗跟随已解析主题；播放器、详情 hero 或其他内容驱动页面需要按实际背景亮度覆盖系统栏时，覆盖结束后 SHALL 恢复已解析主题，而不是重新读取系统默认主题。

#### Scenario: 普通页面系统栏跟随显式模式
- **WHEN** 用户选择与系统状态相反的显式浅色或深色模式并进入普通页面
- **THEN** 状态栏和导航栏图标使用与已解析主题匹配的明暗样式

#### Scenario: 内容驱动覆盖结束后恢复用户选择
- **WHEN** 播放器或详情 hero 临时按内容亮度调整系统栏后退出覆盖状态
- **THEN** 系统栏恢复到用户主题模式解析出的样式
- **AND** 不因系统当前明暗状态而覆盖显式选择
